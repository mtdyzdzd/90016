## Welcome to the Scrum SDLC Documentation Guides

This repository has been designed to help you understand and effectively document the key artefacts used in the **Scrum Software Development Life Cycle (SDLC)**. Scrum emphasizes iterative development, collaboration, and continuous improvement.  

As part of your coursework, you will be developing a **web application for the teaching team**. The project will run across **three sprints**, each lasting **two weeks**, beginning in **Week 6** and concluding in **Week 11** of the semester. Project specifications will be shared at the start of **Week 5**.  

---

## About This Repository

This repository contains **guides and templates** for documenting Scrum SDLC artefacts including:

- 🏁 Project Initiation

- 🧩 Sprint Planning
- 📝 Product Backlog  
- 🗂️ Sprint Backlog  
- 📊 Burn Down Charts
- 💬 Communications Strategy

- 🎛️ Risk Response Monitoring
- 🛡️ Quality Assurance
- 🧑‍🤝‍🧑 Roles and Responsibilities

Each guide explains the **importance of the artefact**, what **details should be captured**, and provides a **template** for your project documentation.

## How to Use This Repository

1. **Refer to the Guides**: The **Guides** folder contains detailed instructions and examples to understand the importance of each Scrum SDLC artefact and how to document the same.  
2. **Modify Core Documents in the Main Folder**: Update **Main** folder documents as needed throughout the project.  
3. **Update Sprint-Specific Documents**: Maintain all required documentation in **Sprint_X** folders during and at the end of each sprint. Should you have any other documentation to update to track the progress of your sprint (that are not mentioned in the SDLC Sprint Artefacts above), check with your subject coordinator first.
4. **Commit Your Changes Regularly**: Follow a structured commit workflow to track all updates efficiently.
